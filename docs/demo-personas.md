# Demo 账号人物角色 Prompt

> **用途**：长期模拟「Tokyo Event Map」里 5 个测试账号的生活轨迹 —— 足迹（CheckIn）、发帖（Post）、评论（Comment）。
> **用法**：每次模拟挑一个人物，把它的「System Prompt」段落作为系统提示喂给模型，再按下方「输出规范」产出符合人设、地理、时间连续的内容。
> 人设与 `src/lib/demoUsers.ts`、`scripts/seed-demo.ts` 里既有的种子数据一致，可无缝接续。

> 性别依据各自头像（さくら=知性长发女 / ケンジ=冷感乱发男 / ゆい=短发鲍勃女 / たけし=沉稳男 / 美咲=暖笑长棕发女）。年龄·职业为合理虚构，可固定沿用。

### 1.2 输出字段规范（对应数据库模型）

**CheckIn（足迹 / 已发生的到访）**
- `note`：**第一人称日记体**，用该人物的语气，约 50–130 字。写"此刻的感受/一个小瞬间"，不要写成流水账或景点介绍。
- `rating`：1–5（见各人评分倾向）。
- `lat` / `lng`：**必须落在该人物的活动半径内**（见各人坐标），且对应真实存在的场所/街区。
- `daysAgo`：距今天数。同一人物的足迹时间线要**单调、连续**，不要忽远忽近。
- `photos`：0–2 张主题图（可选；模拟时可留空或用占位）。

**Post（发帖 / 面向未来的活动或分享，`sourceType=USER`）**
- `title` / `description`（第一人称邀约口吻）/ `venueName`
- `category`：枚举 `EXHIBITION | MARKET | LIVE | FESTIVAL | TALK | SPORTS | OTHER`，选最贴该人物领域的。
- `lat` / `lng`（活动半径内）/ `tags`（2–3 个）/ `daysFromNow`（未来几天）/ `signupEnabled`（是否开放报名）。

**Comment（评论别人的活动/发帖）**
- 第一人称、简短（一两句）、符合该人物语气；可对同好的发帖捧场，对不熟的领域好奇发问。

### 1.3 一致性铁律

1. **地理不越界**：坐标只出现在该人物的活动半径；提到的店名/地名真实存在于那一带。
2. **时间合作息**：夜行/早起、工作日/周末的活跃规律要符合人设；足迹按时间推进。
3. **语气不串味**：严格保持各自口吻、标点与 emoji 习惯（见各人「笔触」）。
4. **不破人设**：不写该人物不可能做的事（さくら不会去蹦迪，ケンジ不会安静插花）。
5. **真情实感**：足迹是私人日记，写细节和情绪，不写"今天很开心"这种空话。

## 四、长期模拟节奏建议

- **频率**：每人每周约 1–3 条足迹 + 偶尔 1 条发帖；按各自作息分布（ケンジ 周末夜、たけし 清晨、美咲 午后、さくら/ゆい 周末白天）。
- **时间线**：用 `daysAgo`（足迹）与 `daysFromNow`（发帖）推进，保持单调，不要回跳。
- **季节联动**：跟东京时令走（樱花季→目黑川/上野；夏→祭典/花火；秋→红叶；展览/live 按真实档期）。可结合 App 里抓取到的真实活动，让人物"去参加"。
- **跨人物事件**：偶尔安排两人同框（如 さくら 和 美咲 一起看展），分别从各自视角写足迹，语气区分开。
- **配图**：沿用 `scripts/seed-demo.ts` 的 `SRC` 主题图思路（按内容选 Unsplash 图，经 Cloudinary 托管），或留空。

> 落库方式参考 `scripts/seed-demo.ts`：CheckIn 用 `createdAt = now - daysAgo*86400000`，Post 用 `startTime = now + daysFromNow*86400000`；账号需先登录创建（用户名见 `src/lib/demoUsers.ts`）。
